## Керування станом та взаємодія компонентів (Лабораторна 2.1)

### Карта стану застосунку

| Значення стану | Природа даних | Власник стану | Споживачі | Дія скидання / зміна |
| :--- | :--- | :--- | :--- | :--- |
| `apparelItems` | Початкові предметні дані | Модуль `src/data/items.js` | `App`, `ProductSelectionProvider`, `CatalogContainer` | Статичні дані (не змінюються) |
| `detailsOpen` | Локальний стан інтерфейсу | `ProductCard` | Конкретний екземпляр картки | Функціональне перемикання кнопки |
| `query`, `availableOnly` | Стан фільтрації каталогу | Власний хук `useProductFilters` (контекст `HomePage`) | `ProductFilters`, `ProductList` | Кнопка «Скинути фільтри» (`resetFilters`) |
| `selectedId` | Спільний стан вибору дропу | `ProductSelectionProvider` (Context API) | `CatalogContainer`, `RequestContainer` (`OrderPage`) | `clearSelection()`, вибір іншого дропу |
| `draft` | Керована чернетка замовлення | `OrderPage` | `OrderForm`, `OrderSummary` | Кнопка «Очистити поля», зміна вибору товару (`key`) |
| `visibleItems` | Похідний список | Обчислюється під час рендеру | `ProductList` | Автоматично при зміні `query` або `availableOnly` |
| `selectedItem` | Похідний предмет | Обчислюється в провайдері (`items.find`) | `RequestContainer` -> `OrderPage` | Автоматично при зміні `selectedId` |

### Обґрунтування засобів керування станом

1. **Локальний стан (`useState`)**: використано в `ProductCard` для `detailsOpen`, оскільки стан розгортання опису однієї речі не впливає на інші картки каталогу та не потрібний за межами цього компонента.
2. **Власний хук (`useProductFilters`)**: інкапсулює стан текстового пошуку, прапорця наявності, обчислення похідного списку та логіку скидання. Відокремлює логіку фільтрації від розмітки `HomePage`.
3. **Підняття стану до предка (`OrderPage`)**: чернетка замовлення (`draft`) потрібна одночасно формі введення `OrderForm` та блоку підсумку `OrderSummary`. Стан піднято до їхнього спільного батька `OrderPage`, а поля оновлюються через функціональну незмінну форму `setDraft((prev) => ({ ...prev, [field]: value }))`.
4. **Контекст вибору (`ProductSelectionContext` + `ProductSelectionProvider`)**: стан обраного товару потрібен двом незалежним гілкам робочої області — каталогу (для підсвічування та кнопки вибору) та секції передзамовлення. Використано провайдер із обмеженою областю дії над робочою зоною сторінок (шапка та навігація залишені поза ним).
5. **Синхронізація з DOM (`useEffect`)**: у `OrderPage` використано ефект для оновлення `document.title` з назвою обраного дропу. При розмонтуванні або виборі іншого товару функція очищення відновлює початковий заголовок вкладки.
6. **Життєвий цикл стану та ключ (`key`)**: у `RequestContainer` на компонент `OrderPage` встановлено атрибут `key={selectedId ?? 'empty'}`. При виборі нового дропу екземпляр сторінки монтується заново з порожньою чернеткою, що виключає випадковий перенос введених мірок і коментарів на інший товар.
